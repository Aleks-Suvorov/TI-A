# TI-A on TradingView

**If you just want it on a chart, read [`START_HERE_TRADINGVIEW.md`](START_HERE_TRADINGVIEW.md).**
That page is written for someone who does not code: copy, paste, click, and a
list of what you should see. This page is the engineering view.

| File | Purpose |
|---|---|
| `TIA.pine` | the indicator — arrows, stop/target lines, diagnostics card, alerts |
| `TIA_strategy.pine` | the same signals through TradingView's broker emulator |
| `frozen_model.json` | the trained constants both consume, generated by Python |
| `START_HERE_TRADINGVIEW.md` | install, smoke test, expected behaviour, troubleshooting |

## Two modes

**A — Frozen Research Model.** The exported model through its original gate:
90% posterior credence that expectancy net of modelled costs is positive.
Measured over 22,626 daily bars of six ETFs it takes **5 trades**. That gate
has deliberately not been relaxed. When it declines it prints the arithmetic.

**B — Practical Observation Mode** (default). The same engines, the same
regime posterior, gated on a reliability-weighted blend with a 1–5 strictness
slider. 97 entries over the same 22,626 bars at default strictness.

Mode B fires on noise — about 21 entries per 4,000 bars of synthetic
martingale, where Mode A fires zero or one. Mode B shows you what the engines
react to. It is not evidence that what they react to is tradeable.

## The five outputs

```
FLAT  --BUY-->   LONG      LONG  --SELL-->  FLAT
FLAT  --SHORT--> SHORT     SHORT --COVER--> FLAT
```

`SELL` closes a long and never opens a short. A same-bar reversal is
forbidden; the cooldown enforces at least one bar flat. Stop and target hits
emit `SELL`/`COVER` like any other exit — an exit that prints nothing is a
hole in the contract, and was a real defect (see `CHANGELOG_TRADINGVIEW.md`
R2).

## The shared core

Everything from the frozen-model block through the two gates lies between
`// ==== BEGIN SHARED CORE ====` and `// ==== END SHARED CORE ====` and is
**byte-identical** in both files.
`python/tests/test_pine_port.py::test_indicator_and_strategy_share_an_identical_core`
fails the build if that stops being true, so the strategy cannot trade
something the indicator does not paint. Edit the core in `TIA.pine`, then
re-splice:

```bash
cd python && PYTHONPATH=src python3 - <<'PY'
from pathlib import Path
ind = Path("../pine/TIA.pine").read_text()
b = ind.index("// ==== BEGIN SHARED CORE ====")
e = ind.index("// ==== END SHARED CORE ====") + len("// ==== END SHARED CORE ====")
st = Path("../pine/TIA_strategy.pine")
t = st.read_text()
tb = t.index("// ==== BEGIN SHARED CORE ====")
te = t.index("// ==== END SHARED CORE ====") + len("// ==== END SHARED CORE ====")
st.write_text(t[:tb] + ind[b:e] + t[te:])
PY
```

The core requires exactly two names from its host file: `isModeA` and
`strictIn`. A test enforces that too.

## Regenerating the frozen model

```bash
cd python
PYTHONPATH=src python3 -m tia.cli export          # trains, writes json, emits into both .pine
```

or, to re-emit without retraining:

```bash
cd python && PYTHONPATH=src python3 -c "from tia.export import emit_pine_constants; \
  emit_pine_constants('../pine/frozen_model.json','../pine/TIA.pine','../pine/TIA_strategy.pine')"
```

Only the region between the `BEGIN/END FROZEN MODEL` markers is rewritten.
`FM_HASH` carries the config manifest hash, and a test compares it against
`frozen_model.json` — a stale script fails the build rather than trading a
model nobody has.

## Checking the port

```bash
cd python
python3 tools/pinelint.py                          # 16 static rule families, both files
PYTHONPATH=src python3 -m pytest tests/test_pine_port.py -q
PYTHONPATH=src python3 tools/pinesim.py --real     # replay the port's arithmetic on real ETFs
```

`pinesim.py` transliterates the Pine arithmetic into Python, driven by the same
`frozen_model.json`, and reports signal counts, the binding gate, and whether
anything went non-finite. It answers *"when it runs, does it do anything?"* —
it does **not** prove the file compiles. Only TradingView can do that; the
manual checklist is at the end of `CHANGELOG_TRADINGVIEW.md`.

## Honest limitations

**No file here has been compiled by TradingView.** No Pine compiler was
available in the environment these were written in. Everything above is static
analysis plus a behavioural replay.

* **No `request.security` anywhere.** The higher timeframe is aggregated
  in-script from five closed chart bars. The previous build passed
  mutable-variable expressions to `request.security` — a compile error — and
  assembled timeframe strings that were invalid on weekly charts. A test fails
  if `request.security` returns.
* **Pine cannot learn.** The Edge Book, the correlation matrix and the
  calibration map are frozen at export. A live Python system keeps updating
  them; this does not.
* **Pine sees one chart.** The system's statistical power comes from pooling
  the Edge Book across a universe. A single-symbol TradingView backtest is
  *statistically uninformative* about whether the edge is real — it can
  falsify, never confirm.
* **The variance-ratio statistic is approximated.** The homoskedastic form
  with a frozen null scale, not the heteroskedasticity-robust one, which
  over-reads trend persistence during volatility clusters. The largest
  fidelity gap; `docs/11-PINE-PLAN.md` §3.
* **Spread estimation is omitted**, replaced by the model's own 5bp fallback.
* **Intraday participation carries a session cycle** the Python reference
  removes by normalising within time-of-day buckets. Prefer daily bars, or
  expect sweep detection to fire more readily near the open and close.
* **The current `frozen_model.json` was trained on synthetic data.** It is a
  smoke test. Do not trade it.

`CHANGELOG_TRADINGVIEW.md` Part 4 lists every omitted and approximated feature
with the reason. None of them makes the port look better than the reference.
